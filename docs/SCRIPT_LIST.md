# Script list

Every C# script in the game, with what it does. There are 109 scripts.

Each script has a note at its very top. The note says what the script does and how it works, in plain English, then gives a technical gist.
This list is the "What it does" part of each note. Open the script to read the rest.

Scripts in `Assets/Editor` run only in the Unity editor. Scripts the battle board does not use say so in their first lines.

## Assets

- **[TestUIKeyControler.cs](../Assets/TestUIKeyControler.cs)**: A test script that controls the older ship screens (UIController) from the keyboard. It is on the Demo, Prototype, Prototype Dev, UI and Canvas_CRT scenes. The battle board does not use this script.

## Assets/Editor

- **[DebrisFieldEditor.cs](../Assets/Editor/DebrisFieldEditor.cs)**: This is the Inspector for a Debris Field in a level. It shows the field's settings and adds two buttons, Scatter and Reshuffle. It is an editor tool. The game itself does not use it.
- **[LevelWindow.cs](../Assets/Editor/LevelWindow.cs)**: This is the Level window (Starwolf > Level), an editor window for building levels. Each level is a small scene in Assets/Scenes/Levels. The window opens a level on top of the battle board and shows it from above as a map. You pick, move, resize, add and delete its parts there.
- **[PowerManagerEditor.cs](../Assets/Editor/PowerManagerEditor.cs)**: This is the Inspector for PowerManager, the older power script. That script is on the PlayerShip prefab and in the Demo scene. This Inspector keeps the power numbers up to date during play mode. The battle board does not use this script.
- **[ReadOnlyDrawer.cs](../Assets/Editor/ReadOnlyDrawer.cs)**: This file changes how two kinds of marked settings look in the Inspector. A setting marked [ReadOnly] shows greyed out and cannot be edited. A text setting marked [Scene] shows as a slot you can drop a scene into. Both work in the editor only.
- **[StarwolfArtWindow.cs](../Assets/Editor/StarwolfArtWindow.cs)**: This is the Art window (Starwolf > Art). It lists every picture in one place: first the prefabs, then the open scenes. You swap a picture by dropping a new one in its box.
- **[StarwolfTuningWindow.cs](../Assets/Editor/StarwolfTuningWindow.cs)**: This is the Tuning window (Starwolf > Tuning), the editor window for changing game numbers. It has six tabs: Ship, Enemy, Board, Keys, Hard Points and Ranges. Changes to a ship's stats file are saved at once. A running game uses them at once.
- **[WindowsBuildCheck.cs](../Assets/Editor/WindowsBuildCheck.cs)**: This stops a Windows build of the game unless it is set to Intel 64-bit. On a Mac with an Apple chip, Unity sets Windows builds to ARM 64-bit. Normal Windows PCs will not open those. It runs in the editor, at the start of every build.

## Assets/Editor/Playtest

- **[PlaytestRunner.cs](../Assets/Editor/Playtest/PlaytestRunner.cs)**: This is the full playtest. It plays the game by itself in the editor and checks over 200 things on the way. It films the run and writes a report. Start it from Starwolf > Playtest > Run power-up playtest.

## Assets/Scripts

- **[Asteroid.cs](../Assets/Scripts/Asteroid.cs)**: A rock that guns can shoot to pieces. It belongs to the older physics weapons, where shots are real moving objects. No scene or prefab has it. The battle board does not use this script.
- **[Autopilot.cs](../Assets/Scripts/Autopilot.cs)**: An autopilot for the older physics ship (PlayerShip). It flies the ship to a point, or keeps it side-on to a target at a set distance. No scene, prefab or other script turns it on. The battle board does not use this script.
- **[CommsManager.cs](../Assets/Scripts/CommsManager.cs)**: An older radio game: a signal comes in, the game pauses, and the player tunes in to catch it. It is on an object in TestScene and works with the older UIController screen. The battle board does not use this script. The board's comms are in other scripts.
- **[ControllerHaptics.cs](../Assets/Scripts/ControllerHaptics.cs)**: Makes a game controller rumble when a gun fires, the ship is hit or the power is switched. With no controller plugged in, it does nothing. It is in every scene, the battle board included. Only the older physics ship and gun scripts ask it for a buzz.
- **[EnemyShip.cs](../Assets/Scripts/EnemyShip.cs)**: An older enemy ship that flies as a physics object. It wanders, chases the player's ship, circles it and shoots lasers at it. It is on the EnemyShip1 and EnemyShip2 prefabs, used in the Prototype Dev scene. The battle board does not use this script.
- **[GameClock.cs](../Assets/Scripts/GameClock.cs)**: An older mission clock. It counts game time from a mission's start and stops when a time limit runs out. It is in the Prototype Dev scene, and no other script reads it. The battle board does not use this script.
- **[GameManager.cs](../Assets/Scripts/GameManager.cs)**: An older match setup for the physics ships. It places the player's ship and enemy groups, then waits for a win or a loss. It is on an object in the Demo, TestScene, Prototype, Prototype Dev and Canvas_CRT scenes. The battle board does not use this script.
- **[HullSystem.cs](../Assets/Scripts/HullSystem.cs)**: The hull of the older physics player ship, split into four sides with separate health: port (left), starboard (right), prow (front) and aft (back). It is on the PlayerShip prefab. The battle board does not use this script. The board's damage is in DamageSystem.
- **[InternalSubsystems.cs](../Assets/Scripts/InternalSubsystems.cs)**: The parts inside the older physics player ship: bridge, sensors, reactor, engines, magazine, life support and crew. It is on the PlayerShip prefab. Once a hull side is broken, hits on that side damage the parts behind it. The battle board does not use this script.
- **[PlayerShip.cs](../Assets/Scripts/PlayerShip.cs)**: The older player ship, flown directly as a physics object with the keyboard or a game controller. It is on the PlayerShip prefab, used in the Demo, TestScene, Prototype, Prototype Dev and Canvas_CRT scenes. The battle board does not use this script. The board's ship is in Ship.
- **[PowerManager.cs](../Assets/Scripts/PowerManager.cs)**: The power system of the older physics player ship. A reactor feeds five power channels: engines, arms (weapons), bay, support and sig (sensors). It is on the PlayerShip prefab. The battle board does not use this script. The board's power is in PowerSystem.
- **[Radar.cs](../Assets/Scripts/Radar.cs)**: The old DRADIS screen of the older physics player ship, named Radar in the code. It places a dot for each nearby ship on a round screen in the older UIController panel. It is on the PlayerShip prefab. The battle board does not use this script. The board's DRADIS is in SensorSystem and PlotPanel.
- **[RadarTarget.cs](../Assets/Scripts/RadarTarget.cs)**: Marks a ship to show as a dot on the old DRADIS screen of the older physics ship. That screen is the Radar script. It is on the EnemyShip1 and EnemyShip2 prefabs. The battle board does not use this script.
- **[Shields.cs](../Assets/Scripts/Shields.cs)**: An energy barrier for the older physics player ship. It takes the damage from hits before the hull does. It shows as a coloured picture around the ship. It is on the PlayerShip prefab. The battle board does not use this script.
- **[ShipStability.cs](../Assets/Scripts/ShipStability.cs)**: A stability meter for the older physics player ship. Hard turns and dodges use it up, and it refills over time. It is on the PlayerShip prefab. The battle board does not use this script.
- **[Weapons.cs](../Assets/Scripts/Weapons.cs)**: An older laser gun for the physics ship that passes every request on to LaserWeapon. No scene, prefab or other script uses it. The battle board does not use this script. The board's guns are in WeaponSystem.
- **[WorldBoundary.cs](../Assets/Scripts/WorldBoundary.cs)**: The edge of the play area for the older physics player ship. A ship that stays outside too long is charged with cowardice and destroyed. It is on an object in the Prototype Dev scene. The battle board does not use this script. The board's edge rule is in ShipState.

## Assets/Scripts/Game

- **[BoardManager.cs](../Assets/Scripts/Game/BoardManager.cs)**: The main script of the battle board. It is on the board's top object in the battle scene. It runs the game clock and takes every click on the board. It plays the board's beeps and tells every panel when to redraw.
- **[Campaign.cs](../Assets/Scripts/Game/Campaign.cs)**: The list of campaign missions, in order. The list is one file in the project: Assets/Campaign/Campaign.asset. The sector map reads it and shows one dot per mission.
- **[DebrisField.cs](../Assets/Scripts/Game/DebrisField.cs)**: A debris field is a shape in a level filled with pieces of wreckage, rock or station. It is placed in the level scenes. Its pieces are real copies saved in the level under this object. The field is the same every play. Only the editor tools use this script.
- **[EndCard.cs](../Assets/Scripts/Game/EndCard.cs)**: The end card. It shows after the campaign's last mission is won. The story's closing line types in on a black screen. Then the title loads, where STARWOLF flickers in.
- **[GasCloud.cs](../Assets/Scripts/Game/GasCloud.cs)**: A gas cloud is a box of cold gas placed in a level. Ships fly through it and take no damage. Our ship's signal drops while it is inside. An enemy can only see our ship in the cloud from close by.
- **[Mission.cs](../Assets/Scripts/Game/Mission.cs)**: A level's goal. A Mission object is placed in a level scene, added from the Level window. It tells the board's QuestSystem what this level asks for. A level without one plays Wolf Hunt.
- **[QuestSystem.cs](../Assets/Scripts/Game/QuestSystem.cs)**: Decides when a mission is won or lost. It is on the battle board. It checks the mission once per board step, after the ships have moved and fired. It shows the help bubble that says what to do in a level.
- **[SaveGame.cs](../Assets/Scripts/Game/SaveGame.cs)**: The campaign's save files. There are three save slots, one small text file each, in the folder Unity gives the game on that computer. It is not on any object. The save slots screen, the sector map, the ship rooms, the end screen and QuestSystem call it.
- **[SaveSlots.cs](../Assets/Scripts/Game/SaveSlots.cs)**: The SAVE SLOTS screen. It is in the SaveSlots scene. It shows three rows, one per save. Picking an empty row starts a new campaign. Picking a used row goes on with that campaign. Either one opens the sector map.
- **[SectorMap.cs](../Assets/Scripts/Game/SectorMap.cs)**: The SECTOR MAP screen of the campaign. It is in the SectorMap scene. It shows the campaign's missions as dots on a star chart. Click a dot to read its mission, then launch it.
- **[ShipRooms.cs](../Assets/Scripts/Game/ShipRooms.cs)**: Our ship between campaign missions. It is in the Ship scene. There is a tab for each room, and a SECTOR MAP tab to go on. Each room is one picture with people in it. Click a person to talk.

## Assets/Scripts/Interfaces

- **[IDamageable.cs](../Assets/Scripts/Interfaces/IDamageable.cs)**: This lists four things that any object that can be hurt must be able to do. The older physics ships, shots and asteroids use it. The battle board does not use this script. Board damage goes through DamageSystem.

## Assets/Scripts/Systems

- **[CommsSystem.cs](../Assets/Scripts/Systems/CommsSystem.cs)**: One ship's radio. Our ship has one, and every enemy and battle group ship has one too. The Comms panel on the board reads and changes our ship's radio. You tune to a message, lock onto it, then turn four letter dials to decode it.
- **[DamageSystem.cs](../Assets/Scripts/Systems/DamageSystem.cs)**: One ship's damage: its armour, its rooms, its crew, fires, air loss and radiation, and its repairs. Our ship has one, and every other ship has one too. The Engineering panel on the board shows our ship's damage and gives the repair orders.
- **[HangarSystem.cs](../Assets/Scripts/Systems/HangarSystem.cs)**: One ship's hangar: its fighters and assault boats, the launch steps, and the craft in flight. Every ship has one. The Hangar panel on the board shows our ship's hangar. Our ship's stats file gives it no fighters. Its hangar starts on the assault boats.
- **[NavSystem.cs](../Assets/Scripts/Systems/NavSystem.cs)**: One ship's movement: where it is, how fast it goes, the way it faces, and its throttle. Every ship has one. The Helm panel on the board steers our ship through it. It puts the ship's 3D model in the right place.
- **[OrdersSystem.cs](../Assets/Scripts/Systems/OrdersSystem.cs)**: One ship's orders station: its alert condition, its AUX charge, and the repair orders paid from that charge. Every ship has one. The Orders panel on the board shows our ship's orders station.
- **[PowerSystem.cs](../Assets/Scripts/Systems/PowerSystem.cs)**: One ship's reactor and its four power buses: ENG, WEP, SEN and AUX. Every ship has one. The Power panel on the board shows our ship's buses and lets the player switch them.
- **[SensorSystem.cs](../Assets/Scripts/Systems/SensorSystem.cs)**: One ship's sensors: DRADIS, the ACTIVE SCAN cone, and the ship's signal (how easy it is to hear). Every ship has one. The Sensors panel on the board shows and sets our ship's sensors. It decides what other ships are heard, scanned and in sight.
- **[Ship.cs](../Assets/Scripts/Systems/Ship.cs)**: The main script on every ship object: our ship, the Garuda and the battle group ships. It points at the ship's stats file in Assets/Ships. The ship's systems (NavSystem, PowerSystem and the rest) read their numbers through it. It sizes the ship's 3D model.
- **[ShipState.cs](../Assets/Scripts/Systems/ShipState.cs)**: The shared state of one ship in a fight. BoardManager keeps one for our ship, and every panel on the board reads it. WorldContact makes one for each other ship. It joins the ship's eight systems together. It keeps what is not in any one system: contacts, plot marks, the periscope and the battle space.
- **[ShipStats.cs](../Assets/Scripts/Systems/ShipStats.cs)**: The shape of a ship's stats file: all of one ship's game numbers in one file. The files are in Assets/Ships, one per ship, for example Asura and Garuda. The Tuning window edits them.
- **[WeaponSystem.cs](../Assets/Scripts/Systems/WeaponSystem.cs)**: One ship's weapons: fire control, the shots in flight, and the PDCs. Every ship has one. The Fire Control panel on the board aims and fires our ship's weapons. The ship's stats file lists its weapons. Our ship has the railgun on its nose, four PDC groups and two torpedo launchers.

## Assets/Scripts/Tactical

- **[BattleSpace.cs](../Assets/Scripts/Tactical/BattleSpace.cs)**: A Battle Space sets how big a level's battle space is, in units. It is placed in a level scene, one per level. A level without one keeps the size set on the board's BoardManager.
- **[CssEase.cs](../Assets/Scripts/Tactical/CssEase.cs)**: This is a speed curve for moving things on the board, such as sliding drawers and flipping rockers. It uses the same curves as a web page, written as four numbers. It does not run by itself. Other board scripts use it.
- **[EnemyBrain.cs](../Assets/Scripts/Tactical/EnemyBrain.cs)**: This is the mind of a computer-run ship: the Garuda, the ships of our battle group, and a ship that runs from us, like the pirate corvette. It listens for our ship, decides where to go and fires its weapons. It only sets its ship's ordered heading and throttle. The ship then moves by the same rules as ours.
- **[EnemySpawn.cs](../Assets/Scripts/Tactical/EnemySpawn.cs)**: An Enemy Spawn marks where an enemy ship starts in a level. It is placed in a level scene. It shows only in the Scene view and the Level window. It sets how that enemy behaves in this level: whether it hunts us, its cruise speed, its patrol route and its radio messages.
- **[GammaBoardPresenter.cs](../Assets/Scripts/Tactical/GammaBoardPresenter.cs)**: This makes the battle board's see-through layers mix their colours the way a web browser does. It is in the board scene, and in the Ship and Fire Control Codex scenes.
- **[PlayerSpawn.cs](../Assets/Scripts/Tactical/PlayerSpawn.cs)**: A Player Spawn marks where our ship starts in a level, and the way it faces. It is placed in a level scene, one per level. It is seen only in the Scene view and the Level window.
- **[ScreenFlow.cs](../Assets/Scripts/Tactical/ScreenFlow.cs)**: ScreenFlow moves the game from one screen to the next. It is in the menu and story scenes: the title, the briefing, the save slots, the sector map and the ship rooms. Buttons and menus call it to load the next scene or to start a level.
- **[ShipView.cs](../Assets/Scripts/Tactical/ShipView.cs)**: A ShipView is a small camera that films one 3D ship model from straight above. It makes a square picture, and the plot shows it as the ship. The board scene has one for our ship and one for an enemy ship's model. More are copied during play.
- **[TacticalWorld.cs](../Assets/Scripts/Tactical/TacticalWorld.cs)**: TacticalWorld is the real world behind the battle board: our ship, the other ships and the level's rocks, in units (x east, y north). It is on the World object in the board scene. It moves the other ships, checks crashes, and writes true bearings and ranges into the board.
- **[TuneAttribute.cs](../Assets/Scripts/Tactical/TuneAttribute.cs)**: This is the [Tune] mark. A setting on a board script marked [Tune("Section")] shows in the Tuning window (Starwolf > Tuning), under that section. It does nothing in the game itself.
- **[WorldContact.cs](../Assets/Scripts/Tactical/WorldContact.cs)**: A WorldContact marks a ship in the world that is not our ship: the Garuda, an arriving enemy, or a ship of our battle group. It links that ship to its track on the board. In the board scene it is on the Garuda, and on the switched-off copy arriving enemies are made from. The battle group prefabs (Indra, Marut, Varuna) have it too.

## Assets/Scripts/Targeting

- **[Targetable.cs](../Assets/Scripts/Targeting/Targetable.cs)**: Targetable marks a 3D object that the older TargetingSystem can aim at and lock. It is part of the older physics ships and guns. The battle board does not use this script. No scene or prefab has it.
- **[TargetingReticle.cs](../Assets/Scripts/Targeting/TargetingReticle.cs)**: This is the aiming mark the older TargetingSystem shows over a target in the 3D world. It is part of the older physics ships and guns. The battle board does not use this script. No scene or prefab has it.
- **[TargetingSystem.cs](../Assets/Scripts/Targeting/TargetingSystem.cs)**: This is the older aim-and-lock for the 3D physics ships. It puts a reticle on the target under the middle of the screen, and a key locks it. The battle board does not use this script. No scene or prefab has it.

## Assets/Scripts/UI

- **[ArtList.cs](../Assets/Scripts/UI/ArtList.cs)**: A list of pictures and fonts for a part of the board with no panel script. The frame, the tool rail, the systems rail and the time control each have one. So do the console, the alarm strip and the signal box. The menu screens use it too: the Ship, SaveSlots, SectorMap and briefing scenes, and the Escape menu. It lets you swap a picture or a font in one place.
- **[BoardMotion.cs](../Assets/Scripts/UI/BoardMotion.cs)**: How the battle board moves. It is on the board in the battle scene. It slides the six drawers in and out and drops and raises the periscope. It opens the helm and the orders station, and runs the board's small looping animations. It does not read the game.
- **[BoardPalette.cs](../Assets/Scripts/UI/BoardPalette.cs)**: The battle board's colours, in one file: Assets/UI/Board/Palette.asset. Every panel and BoardManager take their colours from it. Change a colour there and the whole board follows.
- **[ClickSpot.cs](../Assets/Scripts/UI/ClickSpot.cs)**: A spot on the battle board that you can click, drag or scroll on. It is on every button, knob, switch and lever of the board. These are in the board scenes and the panel prefabs. It only says what the player touched and where. BoardManager decides what happens.
- **[Eased.cs](../Assets/Scripts/UI/Eased.cs)**: A small helper that moves one number on the battle board smoothly to a new value, over a set time. The board's knob pointers, bars and rings use it. Examples are the SCALE knob, the hangar bars, the sensor gain, the helm ring and the plot's sensor circle. It is not on any object by itself.
- **[MarksGraphic.cs](../Assets/Scripts/UI/MarksGraphic.cs)**: Draws simple shapes on the plot: dots, lines, dashed and dotted lines, rings, filled circles and slices of a ring. It is on several layers of the Plot panel prefab. PlotPanel tells each layer what to draw. The plot marks, the sensor circle, the scan cone, weapon reach rings, contact dots and bearing lines all use it.
- **[Panel.cs](../Assets/Scripts/UI/Panel.cs)**: The shared base of every panel on the battle board: Helm, Power, Plot, Sensors, Fire Control, Comms, Hangar, Engineering, Orders, Periscope and the end screen. Each panel script is built on it. It is never on an object by itself.
- **[PlotGrid.cs](../Assets/Scripts/UI/PlotGrid.cs)**: Draws the grid of squares on the plot, the map in the middle of the battle board. It is on the Plot panel prefab. It draws the edge of the battle space as a heavier line. The grid can be white or amber.
- **[Polygon.cs](../Assets/Scripts/UI/Polygon.cs)**: Draws a filled shape with straight sides, such as a triangle, inside its box on the board. It is on the small arrows in the Helm panel prefab.
- **[Rockers.cs](../Assets/Scripts/UI/Rockers.cs)**: Makes the rocker switches on the battle board slide smoothly between up and down. It is on the board's top object in the battle scene, next to BoardManager. Each rocker's picture shows a fixed state. This script covers the jump with a short slide.
- **[ScopeSight.cs](../Assets/Scripts/UI/ScopeSight.cs)**: Draws the red line picture inside the periscope's round window on the battle board. It is on the Periscope panel prefab. The picture looks down a corridor: ribs that drift inward, rails that run to a small far frame, and a horizon with height marks.
- **[SweepGraphic.cs](../Assets/Scripts/UI/SweepGraphic.cs)**: Draws the DRADIS sweep on the plot: a bright line that turns round our ship, with a faint tail fading out behind it. It is on the Plot panel prefab. It shows while DRADIS is on.
- **[Wedge.cs](../Assets/Scripts/UI/Wedge.cs)**: Draws a filled pie slice inside its box on the battle board. The Sensors panel uses one for the ACTIVE SCAN cone on its dial. The Engineering panel uses them for the ring pieces that show each room's strength.

## Assets/Scripts/UI/Panels

- **[CommsPanel.cs](../Assets/Scripts/UI/Panels/CommsPanel.cs)**: The Comms drawer on the battle board. The player picks a radio band and turns a knob to tune in a signal. They lock onto it, then turn four key dials to decode the message. It is on the Comms prefab. The radio's real state is in CommsSystem; this script draws it and passes on clicks.
- **[EndScreenPanel.cs](../Assets/Scripts/UI/Panels/EndScreenPanel.cs)**: The screen that covers the battle board when a mission ends. It says MISSION COMPLETE, SHIP LOST or MISSION FAILED, why, and how the fight went. Escape in a level opens it as the pause menu. It is on the End Screen prefab.
- **[EngineeringPanel.cs](../Assets/Scripts/UI/Panels/EngineeringPanel.cs)**: The Engineering drawer on the battle board. It shows the damage to our ship: a top-down picture coloured by armour, a row for each room (compartment), and the repair rockers. The player picks a room and throws a rocker to repair it. It is on the Engineering prefab.
- **[FireControlPanel.cs](../Assets/Scripts/UI/Panels/FireControlPanel.cs)**: The Fire Control drawer on the battle board. The player picks a weapon: the railgun, PDCs or torpedoes. They check the firing solution and the charge. Then they throw four arming rockers and pull the fire lever. It is on the Fire Control prefab. The test version in the Fire Control Codex scene uses it too. That version has a target monitor and a big FIRE button in place of the lever.
- **[HangarPanel.cs](../Assets/Scripts/UI/Panels/HangarPanel.cs)**: The Hangar drawer on the battle board. The player picks a squadron and its order, and runs six launch stages. Then they pull the launch lever. RECALL calls the squadron back. It is on the Hangar prefab. The work is done in HangarSystem; this script draws it and passes on input.
- **[HelmPanel.cs](../Assets/Scripts/UI/Panels/HelmPanel.cs)**: The Helm panel on the battle board, for steering and speed. It shows the heading, the throttle and the attitude hold keys. It shows the approach range and mode, and the ship's stability. It reads the helm keys. It is on the Helm prefab. The movement rules are in NavSystem.
- **[OrdersPanel.cs](../Assets/Scripts/UI/Panels/OrdersPanel.cs)**: The Orders station on the battle board. The player sets the alert condition and throws order rockers that spend the AUX charge: a damage control party, SEAL and VENT. Each order acts on the room picked in the Engineering drawer. It is on the Orders prefab.
- **[PeriscopePanel.cs](../Assets/Scripts/UI/Panels/PeriscopePanel.cs)**: The Periscope panel on the battle board. It is the targeting computer. The player turns the round sight onto a ship. They zoom until the ship fits the box in the middle. Then they wait for the lock bar to fill. It shows what a scan has found about that ship. It is on the Periscope prefab.
- **[PlotPanel.cs](../Assets/Scripts/UI/Panels/PlotPanel.cs)**: The plot: the map in the middle of the battle board. It draws our ship, other ships, shots, rocks and gas clouds on the grid. It draws the DRADIS circle and the player's POINT, RULER and COMPASS marks. Zoomed in, a close-up shows ships and rocks as lit 3D models with real shot effects. It is on the Plot prefab. Most of its numbers are in the Tuning window.
- **[PowerPanel.cs](../Assets/Scripts/UI/Panels/PowerPanel.cs)**: The Power drawer on the battle board. It shows the reactor and the four power buses: ENG, WEP, SEN and AUX. The player sets each bus to DRAW, STBY or VENT, and can throw the emergency load shed. It is on the Power prefab. The power rules are in PowerSystem.
- **[SensorsPanel.cs](../Assets/Scripts/UI/Panels/SensorsPanel.cs)**: The Sensors drawer on the battle board. The player turns DRADIS and ACTIVE SCAN on and off, and sets the gain and the band. They aim and widen the scan cone, and read the list of contacts. It shows our ship's signal in the drawer and in the signal box. That box is at the top right of the frame. It is on the Sensors prefab. The sensor rules are in SensorSystem.

## Assets/Scripts/Weapons

- **[BoardingPod.cs](../Assets/Scripts/Weapons/BoardingPod.cs)**: A small craft for the older physics weapons, fired by BoardingPodLauncher. It flies to a target ship, sticks to it, and deals damage after a wait. No prefab has this script. The battle board does not use this script.
- **[BoardingPodLauncher.cs](../Assets/Scripts/Weapons/BoardingPodLauncher.cs)**: An older physics weapon that fires a BoardingPod at a chosen ship. WeaponManager can switch to it when it is in WeaponManager's gun list. It is on the PlayerShip prefab, with no pod prefab, no ammo, and not in the gun list. The battle board does not use this script.
- **[BroadsideCannon.cs](../Assets/Scripts/Weapons/BroadsideCannon.cs)**: An older physics weapon: guns on the left and right sides of the player's ship. While fire is held, each side locks onto an enemy beside the ship and fires a shell at it. It is on the PlayerShip prefab, one of the guns WeaponManager switches between. The battle board does not use this script.
- **[Laser.cs](../Assets/Scripts/Weapons/Laser.cs)**: One laser shot for the older physics weapons. It flies as a physics object and damages the ship it hits. It is on the Weapon_Laser prefab, fired by the PlayerShip, EnemyShip1 and EnemyShip2 prefabs. The battle board does not use this script.
- **[LaserWeapon.cs](../Assets/Scripts/Weapons/LaserWeapon.cs)**: An older physics laser gun. It fires Laser shots from a fire point. It is on the PlayerShip prefab, one of the guns WeaponManager switches between. The battle board does not use this script.
- **[Macrocannon.cs](../Assets/Scripts/Weapons/Macrocannon.cs)**: An older physics weapon: a big gun with three barrels that fires Shell shots. Shots hit harder the further away the target point is.
