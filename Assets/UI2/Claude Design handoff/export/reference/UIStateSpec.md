## 1. Architecture

- **One state object** of 68 fields (section 3). Every value on screen is derived from it by `renderVals`, which returns 396 display values.
- **One timer that changes state.** `tickPower` runs every 420 ms. In one update it fills the power buses, repairs the compartment the damage-control party is working, advances the damage-control party, advances the launch sequence, caps sensor gain to the SEN bus, caps thrust to the ENG bus, charges the AUX order pool, charges the weapons capacitor, updates own emissions, advances the mission clock, turns the ship toward the ordered heading. The reactor makes 10 units.
- **One state update per tick.** `tickPower` computes the primary change, then folds every derived value into the same update, so downstream values read the fill this tick is about to commit. An earlier version scheduled derived values separately and they were silently dropped. Do not add a second timer.
- **Animation loops do not change state.** `componentDidMount` use animation frames for drawing only.
- **Render values are pure.** `renderVals` reads state and returns display values. The handlers it returns run only on input. In C#, this maps to binding or a view-model refresh.
- **Gates are functions of state.** Every interlock is a method returning a boolean, a cap or a reason string. Section 4 lists all 32 with their source; section 7 maps how they connect the panels.

### Helpers

```js
function vigenere(text, key, dir) {
  let li = 0;
  return text.split('').map(ch => {
    const i = AZ.indexOf(ch);
    if (i < 0) return ch;
    const k = key[li % key.length];
    li += 1;
    return AZ[((i + dir * k) % 26 + 26) % 26];
  }).join('');
}
```

## 4. Gates and interlocks

Power is the spine: the reactor makes 10 units, and every consumer is capped by what its bus carries. A compartment governs the system housed in it, and a vented compartment counts as integrity zero. Alert condition is a permission gate. The full damage model is specified, not built, in section 09 of `Star Wolf - Design Audit.dc.html`.

### `compHealth`

```js
  compHealth(k) {
    const c = this.state.comp[k];
    if (!c) return 0;
    return c.atmo === 'VENTED' ? 0 : c.integ;
  }

  // Reactor damage caps what the core can make. Floored at 2 units so AUX can always
```

```js
  flip = (id) => () => {
    const order = SWITCHES.map(w => w.id);

        const sw = Object.assign({}, cur);
        for (let j = i; j < order.length; j++) sw[order[j]] = false;
        return { sw, fired: false, lever: 0 };
      }
      if (i > 0 && !cur[order[i - 1]]) return null;
        if (id === 'load' && !this.wepReady()) return null;
        if (id === 'load' && !s.sol[s.sys]) return null;
      if (id === 'load' && s.sys === 'PD' && !s.loaders) return null;
      if (id === 'bearing' && !this.onBearing()) return null;
      if (id === 'arm' && s.wepCharge < this.shotCost()) return null;
      return { sw: Object.assign({}, cur, { [id]: true }), fired: false };
    });
  };
```

## 5. The tick

```js
  tickPower = () => {
    const st = this.state;
    const patch = {};

    // bus fill: drain first so a bus dropping out of DRAW frees its units the same tick
    const fill = Object.assign({}, st.busFill);
    let total = BUSES.reduce((a, b) => a + fill[b.key], 0);
    const coreCap = this.reactorCap();
    let moved = false;
    // only VENT sheds units; STANDBY holds what the bus already carries
    BUSES.forEach(b => {
      if (st.busMode[b.key] === 'VENT' && fill[b.key] > 0) { fill[b.key] -= 1; total -= 1; moved = true; }
    });
    BUSES.forEach(b => {
      if (st.busMode[b.key] === 'DRAW' && fill[b.key] < BUS_MAX && total < coreCap) { fill[b.key] += 1; total += 1; moved = true; }
    });
    if (total > coreCap) {
      for (let i = BUSES.length - 1; i >= 0 && total > coreCap; i--) {
        const k = BUSES[i].key;
        while (fill[k] > 0 && total > coreCap) { fill[k] -= 1; total -= 1; moved = true; }
      }
    }
    if (moved) patch.busFill = fill;

    // the damage-control party: time to work, then the repair lands
    if (st.party) {
      const t = st.party.t + 1;
      if (t >= PARTY_TICKS) {
        const comp = Object.assign({}, st.comp);
        const c = comp[st.party.comp];
        comp[st.party.comp] = Object.assign({}, c, { integ: Math.min(5, c.integ + this.repairRate()) });
        patch.comp = comp;
        patch.party = null;
      } else {
        patch.party = { comp: st.party.comp, t: t };
      }
    }


    // launch telemetry: a thrown stage runs out over several ticks, on this same timer
    const prog = Object.assign({}, st.lprog);
    let ran = false;
    LAUNCH_STAGES.forEach(g => {
      const want = st.lsw[g.id] ? Math.min(100, (prog[g.id] || 0) + g.rate) : 0;
      if (want !== (prog[g.id] || 0)) { prog[g.id] = want; ran = true; }
    });
    if (ran) patch.lprog = prog;

    // everything downstream reads the fill this tick will commit
    const senCap = Math.max(1, fill.sen || 0);
    const engCap = (fill.eng || 0) * 20;
    if (st.senBoost > senCap) patch.senBoost = senCap;
    if (st.thr > engCap) patch.thr = Math.round(engCap);

    const auxRate = (fill.aux || 0) * 3.2;
    if (auxRate > 0 && st.auxCharge < 100) patch.auxCharge = Math.min(100, st.auxCharge + auxRate);

    const wepFeed = (fill.wep || 0) * 5;
    const wepNext = wepFeed > 0 ? Math.min(100, st.wepCharge + wepFeed) : Math.max(0, st.wepCharge - 3);
    if (wepNext !== st.wepCharge) patch.wepCharge = wepNext;

    const sigWant = st.active ? 100 : 0;
    if (st.ownSig !== sigWant) {
      patch.ownSig = Math.max(0, Math.min(100, st.ownSig + (st.active ? 9 : -6)));
    }

    if (!st.paused) patch.missionT = st.missionT + st.rate;

    // the bow swings toward the ordered heading; a damaged engine room swings it slower
    if (st.hdg !== st.ordHdg) {
      const d = ((st.ordHdg - st.hdg + 540) % 360) - 180;
      const rate = Math.max(1, Math.round(4 * this.engFactor()));
      patch.hdg = Math.abs(d) <= rate ? st.ordHdg : ((st.hdg + Math.sign(d) * rate) % 360 + 360) % 360;
    }

    if (Object.keys(patch).length) this.setState(patch);
  };
```

### 7.2 Claims checked

The generator stops if any of these is false in the source.

- SEN caps sensor gain
- ENG caps thrust
- Engine-room damage scales thrust
- WEP gates the arming ladder
- WEP sets capacitor charge
- AUX charges the order pool; orders refuse when dry
- Reactor damage caps units
- Magazine gates the ladder
- Hangar damage gates launch
- Bridge damage gates the firing solution
- A vented compartment counts as integrity zero
- Alert condition releases weapons
- Alert condition releases flight ops
- Condition 1 doubles repair rate
- Active scan raises own emissions
- Only VENT sheds units

### 7.3 Divergence between the tick and the gates

The tick re-applies the sensor and thrust caps from the bus fill it is about to commit, independently of `gainCap` and `thrCap`. The generator runs both over ENG and SEN fill 0–5 and engine-room integrity 0–5 (36 states) with thrust and gain at maximum, and compares.

- Sensor gain: the tick and `gainCap` agree in all 36 states.
- Thrust: 25 of 36 states differ. The tick clamps to ENG fill × 20 without `engFactor()`, so engine-room damage lowers the throttle ceiling on the next drag but does not pull an existing setting down. Example: ENG 1, integrity 0: tick leaves 20, `thrCap` allows 0.

### 8.3 Wheel, text and keyboard

- **Wheel** on the plot: `zoom` × 1.12 per notch toward the operator, ÷ 1.12 away, clamped as the SCALE knob.
- **Text input** (hangar launch bearing, `setLbrg`): non-digits stripped, value wrapped to 0–359, applied on change.
- **Keyboard**: one listener. `A` and `D` step the ordered heading by 3° (`D` clockwise) and clear the attitude hold. Ignored while a text field has focus.

```js
  onKey = (e) => {
    const k = (e.key || '').toLowerCase();
    const tag = (e.target && e.target.tagName) || '';
    if (tag === 'INPUT' || tag === 'TEXTAREA') return;

    if (k !== 'a' && k !== 'd') return;
    this.setState(st => ({ ordHdg: ((st.ordHdg + (k === 'd' ? 3 : -3)) % 360 + 360) % 360, apAtt: null }));
  };
```

### 8.4 Plot tools

Tools, in rail order: `CURSOR`, `POINT`, `RULER`, `COMPASS`, `ERASE`. Picking a tool clears any draft. The key lamp reads `#B6F04A` when selected, `#1A1F23` otherwise. The plot captures the pointer only for `POINT`, `RULER`, `COMPASS`.

- **Units.** Marks are stored in plot-layer px at 1×, own ship at (0,0), y down. 60.9 layer px = 1000 km, the same constant the grid uses. Bearings: 0° north (up), clockwise, rounded to the degree and shown as three digits.
- **CURSOR** (legend SELECT): no plot capture.
- **POINT**: press stamps `{ kind: 'point', x, y, t: missionT }`. Label: the mission clock at placement, hh:mm:ss (`clk`).
- **RULER**: press starts a draft at A, drag moves B. Label at the midpoint: `'RNG ' + km(len) + ' km \u00B7 BRG ' + brg(dx, dy) + '\u00B0'`.
- **COMPASS**: draft ring centred on own ship; the drag sets radius and bearing line. Same label, at the pointer end.
- **Release**: a RULER or COMPASS draft shorter than the threshold in 8.2 is discarded; otherwise it becomes a mark. The draft draws at opacity .75.
- **ERASE**: while selected, marks take clicks and a click deletes that mark; outside ERASE marks ignore the pointer. Pressing ERASE again clears every mark and returns to CURSOR.
- **Constant screen size.** Mark geometry is multiplied by `--lbl` = `invZoom` (`1 / s.zoom`), so marks keep their size across zoom.
- **Ink.** Every colour in the marks block resolves to one value, rgb(74,159,216), own-force blue `#4A9FD8` (checked by colour value, not spelling).
- **Geometry at screen size, px.** Point: width 16, height 16, margin -8, width 7, height 7, margin -3.5, label font 11. Ruler: height 14, margin-top -7, height 1.5, margin-top -.75, width 6, height 6, margin -3, label font 11. Compass: height 1.5, margin-top -.75, label font 11, stroke 1.5 dashed.
- **Assets.** Marks are drawn, not sprites: a dot, a line with end dots, a dashed ring, and TextMesh Pro labels. The rail key glyphs are sprite Group 4.

## 11. Sequences: what the operator does and sees

Generated by `handoff/tools/gen-sequences.js`. Every number below is read from the board source; the script fails if one no longer matches. "Tick" is the power update, every 420 ms (§5), which runs whether or not time is paused.

### Hangar: launching a squadron

1. **Pick the squadron** with the SHIP selector. Each click moves to the next squadron and **clears every launch stage** (all six switches off, all six bars empty). The COMMAND selector steps through that squadron's orders.
2. **Set a launch bearing** in the bearing field (digits only, wrapped to 0–359). The launch is refused while the bearing is more than **60°** from the ship's heading ("BEARING OUTSIDE LAUNCH CONE").
3. **Throw the six launch-stage rockers in order**: CREW, FUEL, ORDNANCE, EVAC, DOORS, CATAPULT. A stage can only be thrown when the stage before it is at 100%. Each stage also passes `stageBlock`, whose refusal text is listed in §10 (flight ops not released at Condition 3, hangar damaged, magazine hit, bay door master shut, no AUX units).
4. **Each stage has a loading bar**: a 5 px bar under its rocker, inside a dark recessed track. While the rocker is thrown the bar fills by a fixed amount every tick, and its width eases over 0.4 s linear between ticks:

| Stage | Fill per tick | Ticks to 100% | Time to 100% |
|---|---|---|---|
| CREW | 22% | 5 | 2.1 s |
| FUEL | 18% | 6 | 2.52 s |
| ORDNANCE | 14% | 8 | 3.36 s |
| EVAC | 20% | 5 | 2.1 s |
| DOORS | 26% | 4 | 1.68 s |
| CATAPULT | 12% | 9 | 3.78 s |

   The bar, the stage lamp and its glow are `accent.caution` amber while the rocker is thrown and filling, and `accent.nominal` green at 100%. An off stage has an empty bar and an unlit lamp (`lamp.offPanel`). The code also assigns `accent.alarm` red to an off stage's bar, but an off stage is always at 0%, so the red never shows. The stage label reads `ink.data` when complete, `ink.label` when the stage can be thrown, `ink.stencil` when it cannot.
5. **Releasing a stage** (clicking a thrown rocker) switches off that stage **and every stage after it**, and empties their bars at once.
6. **Pull the launch lever**: drag the cap to the right; full travel is 210 px. It is refused unless every stage is at 100% and `launchBlock` is clear; the launch fires once when the cap passes **0.9** of its travel, and the cap springs back to the left on release.
7. After launch the squadron is marked launched with its order, and its stage rockers refuse further presses. **RECALL** clears the launch for the selected squadron and resets all six stages.

### Fire control: arming and firing

1. **Choose the weapon** with the weapon system selector: RAILGUN → PDC → MISSILE (cycles). The mount selector steps through that system's mounts (RAILGUN: RGA, RGB; PDC: PDA, PDB; MISSILE: VLS); with one mount it does nothing. The warhead selector steps HE → EMP → PENETRATOR. Changing system, mount or warhead, or pressing LOADERS, **clears the whole arming ladder**.
2. **Compute a solution** with the TRACK pushbutton. It needs a selected target that sensors have identified and an undamaged bridge (`briOk`); it stores that target's range, relative bearing and speed for the current system and clears the ladder. The RNG, BRG and SPD knobs then trim the solution; every step clears the ladder (§8.2).
3. **Arm in order** with the four ladder rockers LOAD → ANGLE → BEARING → ARM. Each needs the one before it thrown. LOAD also needs `wepReady` (WEP bus at 2 units or more, magazine intact, weapons released at Condition 2 or 1), a computed solution for the current system, and for the PDC the LOADERS pushbutton on. BEARING needs the periscope within **4°** of the target. ARM needs the capacitor at or above the system's shot cost: RAILGUN 70%, PDC 25%, MISSILE 40%. Releasing a rocker releases it and every rocker after it, and returns the fire lever to rest.
4. **Capacitor**: gains 5% per WEP unit every tick up to 100%, and loses 3% per tick when the WEP bus is empty.
5. **Pull the fire lever**: full travel 210 px; it fires once when the cap passes **0.9** of its travel and only if the whole ladder is set; it springs back on release.

### Power: buses, standby and venting

1. Each of the four buses (ENG, WEP, SEN, AUX) has a mode selector that steps VENT ↔ STANDBY ↔ DRAW and reverses at each end.
2. Every tick: a bus in VENT loses 1 unit; a bus in DRAW gains 1 unit if it holds fewer than 5 and the total is below the reactor's cap; STANDBY holds what it has. If the total exceeds the cap (reactor damage), units are removed from the last bus first.
3. The EMERG LOAD SHED rocker puts all four buses into VENT when thrown and back to STANDBY when released. While it is thrown the bus selectors refuse.
4. What the buses feed, on the same tick: sensor gain is capped at the SEN units (minimum 1), thrust at ENG units × 20 (see §7.3 for the engine-room divergence), the order pool gains 3.2% per AUX unit, and the capacitor as above.

### Sensors: listen, then look, then ping

1. **DRADIS** rocker: passive listening on or off. **ACTIVE SCAN** rocker: active emission on or off; own emissions rise 9 per tick to 100 while it is on and fall 6 per tick when off.
2. **Array gain fader**: 1 to 5, capped by the SEN bus. Sensor range is 12000 km + 7000 km per gain step; the UV band hears to 0.55 of that.
3. **Spectrum keys** THERM / RAD / UV / EM choose the band; a contact is heard only if it emits in that band and is within range.
4. **Active scan cone**: drag round the dial to set its bearing; NARROW and WIDEN change the arc in 10° steps between 15° and 90°. Releasing the dial identifies every contact inside the cone. A contact-board row identifies its contact if the cone covers it and it is heard.

### Comms: tune, lock, decrypt

1. The band selector steps 1 → 2 → 3 → 1 and **drops any lock**. The carrier is on band 2 at 72.2.
2. The tuning knob (drag round) sets the frequency from 1 to 100 in 0.1 steps (§8.2); any movement drops the lock.
3. The **LOCK** rocker locks only when tuned within ±0.3 of the carrier; otherwise it refuses and shows the gated paddle.
4. The four **decrypt dials** turn only while locked: click steps a letter forward, shift-click back, through A–Z. The dial just moved is highlighted for 1100 ms. The message reads as plain text when the dials spell WOLF.

### Engineering: repairing a compartment

1. Choose the compartment by clicking its cell on the ship schematic, its row on the screen, or the ACTING ON selector.
2. Repair rockers act on that compartment and flick back after 400 ms: **REBOOT** clears the condition and adds 1 integrity; **REPAIR** commits the damage-control party, which works for 6 ticks (2.52 s) and then adds 1 integrity (2 at Condition 1); **SEAL** restores atmosphere; **VENT** vents the compartment and puts out a fire. The order rockers on the orders station apply the same four effects to the same compartment, paid from the AUX pool. Each is refused with the reason in §10 (party already committed, no crew, full integrity, already sealed or vented, nothing to restart). DUMMY 1 and DUMMY 2 are blanking plates.
3. A vented compartment counts as integrity 0 and disables the system housed in it (§4).

### Orders station: alert condition and orders

1. The header stows and opens the station. The alert selector steps Condition 3 → 2 → 1 → 3. Weapons and flight ops are released at Condition 2 or 1; repairs run at double rate at Condition 1.
2. Order rockers spend the AUX order pool: PARTY 30% (+1 integ), SEAL 25% (restore atm), VENT 15% (purge compt). FIRE, BLKHD, SCRUB are unfitted blanking plates. An order with too little in the pool, or refused by `orderBlock`, flashes its failure for 420 ms; every order rocker flicks back after 400 ms.

### Helm

1. The header expands and collapses the helm.
2. Throttle fader: 0 to 100%, capped by thrust available (§4). The ship turns toward the ordered heading by 4° per tick, fewer with engine-room damage (minimum 1°). The A and D keys step the ordered heading by 3°.
3. Attitude hold keys: click to hold, click again to release. Approach range − / + steps 2k, 4k, 8k, 12k, 18k, 24k km. Approach mode keys DIRECT / FLANKING / EVASIVE.

### Periscope

1. The carriage lowers and houses the scope; the housing drops over 0.5 s (cubic-bezier(.24,.9,.26,1)).
2. Drag across the aperture to slew (0.34° per px, §8.2). SLEW jumps to the selected target's bearing. CLASS records the hull class of the contact in view. Any slew releases BEARING and ARM on the fire control ladder.

### Time control, alarm strip and console

1. PAUSE toggles simulation time. The rate keys ×0.25, ×1, ×5, ×10 set the rate and resume; the mission clock advances by the rate in seconds every tick while running.
2. The alarm strip ("3 NEW CONTACTS SINCE COMMIT", blinking lamp) shows from load until it is clicked; clicking acknowledges it and hides it. Nothing on the board raises it again.
3. The SCALE knob zooms the plot (§8.2); the grid tint selector switches WHT and R-O.
